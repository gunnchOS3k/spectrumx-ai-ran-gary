# Prospective fair-control study — design draft only
No new campaign is executed or authorized. This is a local proposal, not independent preregistration. Original/revised protocols, five-seed results and preprint remain unchanged. Design choices below are proposed values requiring a separate milestone and owner approval before outcomes; none was fixed before the historical results.

1. **Hypothesis.** A transition-aware controller using calibrated, delayed estimates improves completed-task service fraction by at least a practically useful amount relative to a matched hysteresis fallback. Test the controller as a whole; isolate prediction information with a separately matched policy pair.
2. **Primary outcome.** Fraction of admitted tasks meeting predeclared latency, output-quality and persistence requirements over a fixed episode, including transition stalls, rejected actions and recovery failures. Define denominators, admission policy and task censoring before simulation. Keep score utility secondary.
3. **Eligible policies.** Cloud fallback, availability-only edge rule, tuned hysteresis, current-slot discrete optimizer and finite-horizon controller, all implemented through one action validator. A full-information dynamic program is a separately labeled privileged reference, never an equal-information competitor.
4. **Common truth.** One pre-generated exogenous workload/network/failure stream per seed, stored immutable and paired across policies. Physical truth state cannot be altered by an observation intervention. Policy-specific batteries/queues/task progress evolve causally under the same exogenous stream.
5. **Observation rules.** Explicit schema, common delay/noise/refresh assumptions and masks; deny undeclared fields. Primary fair pair receives identical samples and prediction horizons; test prediction-information effects in a distinct matched analysis. Log consumed as well as accessible fields.
6. **Action feasibility.** Common available paths/placements, quantized resource/fidelity/checkpoint choices and task constraints. Validate before execution; reject infeasible actions with a frozen fallback rule and count failures. Freeze candidate enumeration and ties. Static actions must face the same validator after outages.
7. **Resource budgets.** Equal bandwidth, CPU cycles, storage and device battery at episode start, with task-dependent consumption and recharge rules fixed in advance. Capacity constrains delivered service, not merely a positive flag.
8. **Compute accounting.** Fix hardware/runtime, count model evaluations, optimization iterations and decision wall time; proposed 100 ms local decision budget (subject to calibration) with explicit deadline fallback. Match algorithm budgets and report offline training/calibration separately. Privileged optimum exempt only as labeled reference.
9. **Switching/handover.** Predeclare category-dependent downtime, energy and data-migration cost; no penalty chosen after seeing rankings. Recompute actions at each prospective cost setting. Include previous action in transition-aware decisions and the same scoring/execution cost for all policies.
10. **Allocation constraints.** Fixed feasible simplex, per-user minimum/maximum, CPU/task coupling and sum constraints with explicit numerical tolerances/projector common to all controllers. Optimize the declared service objective, not an unrelated share surrogate. Verify small instances by enumeration/KKT where applicable.
11. **Correlated failures.** Predefine a coupled state process with shared terrestrial/edge/power events and conditional NTN failure/capacity restrictions. Separate independent and compound-outage scenario strata; do not select the favorable mixture retrospectively.
12. **Calibration.** Use separate calibration inputs for delay/loss/power/estimation error. State empirical versus synthetic parameters. Service fidelity must be validated against task output; prediction fidelity means discrepancy from truth. If physical calibration is unavailable, restrict conclusions to authored simulation priors.
13. **Primary paired comparison.** Transition-aware controller minus matched hysteresis on the primary held-out scenario mixture; one seed-level difference in task fraction per seed. Do not pool original/revised historical generators with new evidence.
14. **Scientific effect.** Proposed minimum practically important improvement 0.02 absolute completed-task fraction. This is a design proposal, not a known detectable or physically justified effect. Owner/domain review must justify or revise it before outcomes.
15. **Seeds/uncertainty.** No new seeds are selected/run now. In the next approved milestone, use separate development pilots to estimate seed-level variance; fix the held-out sample size for target 95% CI half-width<=0.01 and 90% power for the approved minimum effect. Publish calculation, seed generation and stop/cap rules before opening held-out outcomes. If budget cannot achieve precision, classify underpowered; do not quietly add seeds after inspection. Paired t inference plus predeclared robust sensitivity and dependence diagnostics; no episode pseudoreplication.
16. **Multiplicity.** One confirmatory primary contrast/outcome. Secondary controllers, shifts, fidelity and failure subgroups explicitly exploratory or assigned a prespecified Holm family. Equivalence requires a justified margin and a dedicated interval procedure, not p>0.05 or overlapping intervals.
17. **Held-out validation.** Lock unseen failure correlation strengths, observation delays and workload mixes. Separate fixed primary mixture from external-shift diagnostics; forbid tuning on the latter. Preserve all scenarios and failures.
18. **Negative reporting.** Report every planned comparison, seed, infeasibility/timeout, harmful subgroup and inconclusive interval. Abort criteria are implementation correctness or resource caps, never unfavorable means. Distinguish implementation faults from an adequately tested failed hypothesis.
19. **Budget.** Proposed cap 12 CPU-hours total for pilots plus held-out run on recorded hardware, with an approved allocation before execution; audit/resource smoke tests outside held-out outcomes bounded separately. If the seed plan exceeds this cap, redesign before observing outcomes or seek a new approval. This proposal spends no experimental budget now.
20. **Success/failure.** Evidence of a practically meaningful effect requires the prespecified paired interval to support the approved effect criterion with no hidden infeasibility/timing violation. Negative or inconclusive outcome remains a valid result. General network claims require independent held-out/physical validation; successful simulation is insufficient.

Before outcomes: finalize hypothesis, endpoint/denominator, controller code hashes, observation/feasibility rules, calibration, cost model, seed/sample/multiplicity plan, compute/resource cap and success criteria; obtain separate authorization. Physical extension may require measured path delay/loss and outage availability, edge task/queue traces, migration/checkpoint interruption, device power-duration/battery measurements and predictor error. No satellite/device experiment, patent clearance or institutional approval has been completed.
