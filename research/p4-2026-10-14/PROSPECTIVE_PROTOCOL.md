# Paper II prospective fair cross-layer control study — P4 draft v0.1

Question: Does a transition-aware finite-horizon controller improve independently evaluated task-service completion relative to a matched hysteresis baseline when observations,feasible actions,resources and compute opportunities are controlled? Primary practical-superiority null: mean paired improvement<=0.02; planning alternative 0.04,with effect gap 0.02 and owner/domain justification still pending. A separate descriptive zero-effect comparison is retained for harm/inconclusiveness. Superiority is not presumed. Old negative results identify failure mechanisms; they do not tune new parameters or estimate future outcomes.

Primary endpoint: fraction of ALL exogenously released eligible tasks completed correctly,at required service fidelity,before task deadline and within freshness/persistence rules. Rejected admission,defer,invalid action,timeouts and interrupted tasks remain denominator failures. This strengthens the prior local proposal's admitted-task denominator to prevent policy-dependent selection. Evaluation uses independent task outcomes,not controller prediction or the old smooth utility. Secondary: p95delay among successes with completion fraction reported alongside,energy per attempted task,queue/backlog,deadline/recovery failure,invalid actions,resource overshoot,switch count/stall duration,compute time/model evaluations and fairness of delivered task service. No incomplete-task latency survivor claim.

Common truth: immutable exogenous network/workload/failure frames generated once per independent seed. Separate policy queues/task progress/battery/cache state; common transition equations and initial conditions. Observation adapter receives only the same timestamped delayed/noisy estimates and forecast object for both primary policies. True latent failures and realized future truth never enter controller calls. Candidate actions come from public hardware contracts and estimated state; final execution validator uses true availability/capacity and applies the SAME rejection/defer outcome to all. Candidate feasibility queries must not expose truth via side channels. Record declared/consumed observations; equal accessible data does not claim identical internal feature use.

Primary policies: (A) transition-aware beam-search MPC,H=3, beam width 4,lexicographic fixed ties; (B) matched one-step predicted-completion greedy rule with a fixed hysteresis threshold chosen on development data. Both see the same forecast horizon and previous action/battery/task state,can use the same resource/fidelity candidates,and receive maximum 512 model-evaluation calls/decision and the same proposed 100 ms wall deadline. Used computation may differ and must be reported; equal opportunity is the design claim. Future controller implementations must make the predicted task-completion objective/costs exact in code and independently tested before a campaign. Forecast accuracy is a controlled/calibrated assumption,not guaranteed twin fidelity.

Secondary baselines: cloud with availability fallback; simple edge/availability rule exposing the old collapse; matched greedy without hysteresis; fixed-target fidelity; static FIRST choice revalidated each step. All use common valid action/resource constraints and receive same observation object. A full-truth finite-horizon exhaustive optimum is a privileged diagnostic on small instances only,not an eligible equal-information comparator or general upper bound outside its enumerated action/horizon domain.

Actions: available network category,TN/Wi-Fi/NTN; local/edge/cloud placement; a finite allocation catalog with equal/priority/deadline-aware profiles; target/degraded service fidelity with independently justified output-quality thresholds. Per-user bandwidth,per-placement CPU,terminal power and energy/storage budgets must be enforced for every action. Do not optimize symmetric log shares as a surrogate for task success. Candidate spaces/objective units/task demands must be frozen before tuning. An allocation-independent primary metric is a model-design failure gate. Defer is explicit zero-service behavior,not invented continuation.

Transition/state: switching incurs proposed interruption0/50/200ms and migration10/100/500ms plus energy/data movement,not arbitrary score subtraction; durations/calibration provenance must be confirmed. Model causal task progress,queues and battery updates. Reject over-capacity/unavailable actions and account stalls before deadlines. Shared external outages use a prespecified Markov/common-cause process with normal and compound-outage strata. Define TN,edge,NTN gateway/terminal dependencies rather than independent slot draws. No physical channel claim.

Inputs: fixed primary mixture across light/heavy task demand,observation error/delay and correlated outage strata. Proposed rates are dimensioned tasks/s and bytes/cycles/task,not unvalidated service-unit names. Arrival process proposed Poisson with bursty heldout alternative; common scheduled arrivals and task oracle for pairing. Primary delay/loss/capacity,cost and forecast-error parameters remain authored until development calibration on independent sources/adapters. Use low/high load around explicitly measured/modelled service capacity,not select a favorable utilization after heldout. No old raw-result file is an input to new controller tuning.

Validation: construct cases where (i)resources change success,(ii)switching harms service,(iii)an unavailable action fails,(iv)perfect truth differs from delayed observations,(v)quality/freshness fail despite connectivity. Calibrate predictor on a separate development dataset; report residual errors and heldout shifts. Reserve unseen failure-correlation,demand and estimator-error combinations before outcomes. Full-truth diagnostic must not leak into primary policy selection.

Sample/resources: planning target 0.02 and half-width 0.01;40 development-pilot pairs,minimum 30/maximum 2500 heldout pairs selected using t-based precision/power before heldout. HypotheticalSD 0.15 suggests about 900pairs. Each independent pair proposed24 episodes×64 time steps,with predeclared task arrival schedules. Units are independent seed-pair means,not episodes/tasks. Proposed cap 12 CPU-hours total,including pilot/tuning and comparisons; measure per-pair cost on approved development fixtures before final freeze. If sample plan exceeds cap,stop before heldout and revise scientifically; no unplanned optional stopping. Actual seeds remain unassigned here.

Negative-result criteria: interval entirely below 0 = harmful under configured priors; contains0 = inconclusive; above0 but below/straddling practical threshold = statistical improvement without established practical importance. A practical success claim needs the primary lower confidence bound above approved0.02 and no hidden feasibility/compute violations. Sample planning uses effect gap 0.02 between the practical null 0.02 and a hypothetical alternative 0.04,not power to prove an improvement exactly at the boundary. The alternative is a design assumption,not an expected finding. No equivalence claim without a separate margin/procedure. Preserve unfavorable scenarios and model/implementation faults separately.

Preparation scope: fair_control/ implements input/observation/action/compute/statistics/result/provenance contracts plus constructed engineering tests only. It is not a completed calibrated environment,task-execution backend or validated MPC. The next milestone must implement/freeze candidate algorithms and common dynamics,calibrate/approve endpoint/costs,validate on constructed cases,and obtain separate campaign authorization. No campaign runner or holdout data is enabled in P4. This extends,does not modify,the preprint's archived PROSPECTIVE_FAIR_CONTROL_STUDY.md.

## Statistical and reproducibility rules
Use one primary paired contrast, a fixed exogenous workload/scenario mixture and whole-seed/session means. Each policy/model receives the same exogenous inputs in its paired unit; policy-dependent queues/batteries evolve separately. Never pool this study with historical generators. Correctness checks and pilot/training samples are excluded from confirmatory inference. Primary two-sided95% paired Student-t interval, sample SD(ddof1) and paired differences; disclose distribution/dependence assumptions and influential pairs. Secondary bootstrap sensitivity is descriptive at the independent unit; do not resample slots/tasks as independent when clustered. Zero-crossing is inconclusive, not equivalence. Secondary confirmatory families use Holm; remaining subgroups are explicitly exploratory. Report all planned outcomes, harms, missing/invalid actions, timeouts and precision failures.

Planning example uses a hypothetical paired SD 0.15, not measured/calculated from old means. For practical delta 0.02,power 0.90 and two-sided alpha 0.05, normal planning gives approximately592paired units; half-width 0.01 needs865. Use iterative t-quantile planning in Paper II tooling; a40-unit prospective development pilot would estimate SD and select n before any heldout outcome is read, minimum 30, maximum 2500. Starting expectation is about 900units if the hypothetical variance holds, not a fixed guarantee of power. If required n exceeds cap or resource estimate, stop before heldout and revise/seek approval. Pilot variance selection has uncertainty; archive that estimate and sensitivity. These are proposed future counts; no seeds are expanded now. Do not append units after viewing heldout results.

Derive disjoint pilot/training/heldout seed streams from approved study/config SHA and split/index using SHA256; archive actual seed lists and input hashes only in the separately authorized milestone. No reserved future seed list or outcome is created here. Freeze policies, tuning bounds, scenario mixture, n and stopping/multiplicity rules before heldout. An independent reviewer should audit the freeze and holdout access log. Archive source/config SHAs, dependencies, hardware/runtime, observations/actions/rejections/compute/cost traces, raw task outcomes, seed-level summaries, independent analysis, data dictionary and SHA256SUMS. A checksum establishes bytes, not validity or ownership.

Human decisions: approve science/effect size/sampling and device/workload assumptions; settle rights/permissions, intended claims, required coauthors/contributions/funding/conflicts and patent/IP concerns; authorize a separate execution milestone. Human scientific approval and external publication authorization remain false. Synthetic process experiments do not establish a human-participant ethics exemption; studies with people need an appropriate separate review.

P4 statistical-design clarification: the generic sample-size illustration below uses an effect GAP of 0.02; when testing practical superiority over0.02,the planning alternative is0.04. It must not be read as 90% power to demonstrate an effect greater than0.02when the true effect equals0.02. Actual effect/margin choices require human/domain justification before freezing.
